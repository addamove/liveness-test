# В кадре — локальный прототип

Три последовательных шага: фото лица → фото раскрытого паспорта → круговое движение головы → результат с двумя фотографиями и скачиваемым JSON. Интерфейс на русском, адаптирован под телефон, с овальной и прямоугольной рамками.

## Запуск

Требуются Node.js 20.19+ и OpenSSL.

```sh
git clone https://github.com/addamove/liveness-test.git
cd liveness-test
npm install
npm run dev
```

`npm install` копирует модели из npm-пакетов в `public/models/` (~28 МБ). Во время работы модели, WASM и приложение загружаются только с локального компьютера. Для установки пакетов нужен интернет; для использования установленного прототипа — только доступ к компьютеру по сети.

`npm run dev` запускает:

- **HTTPS, порт 5173** — приложение, доступное в локальной сети.
- **HTTP, порт 5174** — страница подключения с QR-кодом, публичным сертификатом и инструкцией для iOS / Android.

Актуальные IP-адреса выводятся в терминале: страница подключения `http://<LAN-IP>:5174` и демо `https://<LAN-IP>:5173`. После изменения сети перезапустите сервер: он выпустит новый сертификат с актуальным IP.

### Телефон

1. Подключите телефон и компьютер к одной Wi-Fi сети.
2. Откройте HTTP-страницу подключения из терминала в Safari или Chrome.
3. Скачайте и установите **V Kadre Local Demo CA**. На iPhone также включите полное доверие: Настройки → Основные → Об этом устройстве → Доверие сертификатам. Подробные шаги есть на странице подключения.
4. Перейдите к HTTPS-демо и разрешите камеру.

Камера через обычный `http://192.168…` не работает: браузеру нужен secure context. Для LAN используется отдельный локальный корневой сертификат и подписанный им серверный сертификат. Скрипт **не меняет** системные настройки доверия. После теста удалите установленный сертификат с телефона. Закрытые ключи находятся в `.certs/`, исключены из Git и запрещены к выдаче Vite; не передавайте их другим людям. HTTP-сервер отдаёт только страницу подключения и публичный `root.cer`.

Если телефон не открывает страницу, проверьте Wi-Fi, VPN, сетевую изоляцию клиентов на роутере и разрешение входящих подключений Node.js в брандмауэре. Управляемое корпоративное устройство может запрещать установку пользовательского CA.

### Только компьютер, без сертификата

```sh
npm run dev:http
```

Откройте [http://localhost:5175](http://localhost:5175). Этот сервер слушает только loopback. Браузеры разрешают камеру на localhost без HTTPS.

## Логика

### Облегчённый режим и автоматический фоллбек

На стартовом экране доступна кнопка **«Снимать по кнопке»**. Она включает камеру без загрузки MediaPipe, OpenCV и их WASM/данных. Два фото снимаются по кнопке с подтверждением после каждого. На третьем шаге показано «Проверка движения недоступна» и доступно явное завершение без проверки. Рамка в ручном режиме служит только подсказкой.

При выборе автосъёмки перед загрузкой моделей проверяется поддержка WebAssembly/WebGL. Известные значения `navigator.deviceMemory ≤ 2 ГБ` или `navigator.hardwareConcurrency ≤ 2` консервативно выбирают ручной режим. Отсутствие этих API не считается признаком слабого устройства: такие устройства проходят пробный запуск. Это приблизительные сигналы, а не определение модели, возраста или точной производительности телефона.

После запуска проверяется реальная скорость: два прогревочных кадра не входят в среднее, затем нужно минимум четыре измерения; скользящее окно — восемь кадров. Ручной режим включается при среднем времени обработки >220 мс, среднем интервале между кадрами >350 мс или трёх подряд обработках >350 мс. Производительность продолжает проверяться на всех трёх шагах; время скрытой вкладки и переключения камеры не включается в оценку.

Ошибка модели, загрузка дольше 12 секунд или зависший вызов распознавания дольше 1.5 секунд тоже переводят на кнопку. Отказ в доступе к **камере** остаётся ошибкой камеры: ручной режим не может обойти разрешения браузера. Пороговые значения находятся в `src/performance.js` и являются стартовыми настройками прототипа.

При фоллбеке новые вызовы детекторов прекращаются, модель лица освобождается после завершения уже начатого вызова. Поздний результат загрузки/распознавания не может вернуть автосъёмку. Ручной режим сохраняется на следующих шагах и при повторном прохождении до явного выбора «Попробовать автосъёмку» или обновления страницы. Уже начатую синхронную работу WASM в основном потоке и загрузку сторонней библиотеки нельзя жёстко прервать таймером: переход произойдёт, когда браузер снова сможет обрабатывать события. Режим по кнопке, выбранный заранее или до загрузки по ресурсным сигналам, полностью избегает запуска моделей.

У каждого снимка в JSON есть `mode`, `validated`, `fallbackReason`, `performance`. Для ручного снимка `validated: false`, `heldMs: null`, `checks: []`; на экране результата явно написано «Без проверки». Условия автосъёмки для таких фото не заявляются выполненными.

### 1. Лицо

Используется именно `@tensorflow-models/face-landmarks-detection` 1.0.6, модель `MediaPipeFaceMesh`, runtime `mediapipe`, `refineLandmarks: true`, `maxFaces: 2`. API TensorFlow.js оборачивает MediaPipe WASM/WebGL; возвращаются 478 точек, включая радужки.

Условия:

- В видимой области ровно одно лицо.
- Все точки контура лица внутри овала, лицо расположено по центру и занимает не менее 62% высоты овала.
- Поворот головы: yaw ≤ 14.95°, pitch ≤ 17.25°, roll ≤ 11.5° по модулю. Углы оцениваются через OpenCV `solvePnP` по шести точкам и канонической 3D-геометрии MediaPipe, с приближёнными параметрами камеры.
- Оба глаза открыты. Радужки примерно по центру глаз; допустимое отклонение относительно ширины глаза: горизонтальное ≤0.23, вертикальное ≤0.115. Допуски взгляда и поворота головы расширены на 15% относительно первой версии. Условия рамки, открытых глаз и удержания 400 мс сохранены.
- Условия непрерывно выполняются **не менее 400 мс**, минимум на трёх свежих проанализированных кадрах. Любое нарушение или промежуток между кадрами >350 мс сбрасывает таймер. Долгая обработка >350 мс тоже не засчитывается.

Уверенное направление взгляда на оптическую ось по обычной RGB-камере не гарантируется. Это эвристика по радужкам и повороту головы, без индивидуальной калибровки, не eye tracker и не liveness/anti-spoofing. Фотография лица на экране тоже может пройти условия — прототип не проверяет живость.

### 2. Раскрытый паспорт

Используется **OpenCV.js 4.12**: контуры Canny и пороговая сегментация, объединение разрывов, выпуклая оболочка и четырёхугольник. Детектор не является обученной моделью. Интерфейс поддерживает два положения разворота: **две страницы рядом** (рамка 1.42:1) и **одна над другой** (рамка 1:1.42).

Поиск кандидата отделён от допуска к снимку. Уже небольшой, смещённый или обрезанный прямоугольник получает янтарный контур. Подсказки предлагают приблизить/отдалить камеру, сдвинуть паспорт в конкретную сторону, выровнять его или показать сгиб. Направления учитывают зеркальное превью. Четыре угла рамки оцениваются отдельно: угол зелёный только при реально видимом угле документа внутри рамки и рядом с соответствующим углом рамки. Потеря контура сразу убирает зелёную подсветку.

Для автоматического фото одновременно нужны:

- Все четыре края полностью видны в видеокадре, углы внутри рамки и возле её соответствующих углов.
- Площадь ≥55% рамки, пропорции соответствуют выбранному развороту, умеренная перспектива.
- Видимый **центральный сгиб**. Кандидат временно выравнивается перспективным преобразованием; ищется непрерывная тёмная полоса около середины между страницами. Для вертикального разворота сгиб горизонтальный.
- Смещение углов <2.5% ширины рамки между кадрами и все условия соблюдены 400 мс.

Обычный ровный лист без сгиба автоснимок не проходит. Но это **эвристика признаков разворота**, которая не гарантирует, что объект — открытый паспорт: напечатанная линия или похожая тень могут имитировать сгиб. Блики, бесконтрастные края и слабо выраженный сгиб дают ложные отказы. Нужен контрастный фон, ровный свет и достаточно расправленные страницы. В ручном режиме интерфейс просит раскрыть паспорт, но не проверяет его.

Для надёжного различения открытого и закрытого паспорта нужен отдельный обученный классификатор/сегментатор и размеченные примеры обоих состояний, разных фонов, освещения и устройств. Текущая настройка OpenCV меняет геометрические и контрастные пороги, без «дообучения». Содержимое, тип, подлинность паспорта и качество фото не проверяются.

### 3. Круговое движение головы

Используется уже загруженный FaceMesh; дополнительная модель не загружается. Курсор третьего шага вычисляется по положению носа относительно линии глаз и подбородка, с нормализацией масштаба, сдвига лица и наклона головы. Это устраняет скачки между решениями `solvePnP`; 3D-оценка остаётся на первом шаге. Медиана трёх отсчётов и сглаживание с постоянной 150 мс подавляют дрожание; одиночные большие выбросы не двигают курсор и не дают прогресса. После 450 мс прямого устойчивого положения запоминается нейтральный поворот. Затем пользователь плавно следует за точкой по часовой стрелке и возвращается в центр. Белая точка показывает оценку движения головы, зелёная — следующую цель.

Проверяются девять последовательных секторов полного круга (последний замыкает первый) и устойчивый возврат в центр. В каждом секторе нужно ненадолго задержаться. Масштаб управления: 18 условных единиц по горизонтали и 13 по вертикали; это приближённые ориентиры движения, не точные углы головы. Радиус попадания допускает диапазон 55–165%, угловой допуск — около 26°.

Краткая потеря лица или сбой до 1.2 секунды ставит проверку на паузу и сохраняет пройденные точки. Длительная потеря лица требует новой калибровки. Центр круга и выбросы не дают прогресса; сглаженная траектория сама по себе тоже не может заработать точку — проверяются и текущие исходные координаты. При движении лицо может немного выходить за овал, если остаётся достаточно крупным и около центра. Скрытие вкладки/открытие справки сбрасывает задание; изменение размера экрана не стирает нормализованную калибровку. Полное выполнение занимает не менее четырёх секунд. Настройки и логика — в `src/liveness.js`.

Это **демо задания на движение**, не надёжный liveness/PAD: оно не проверяет глубину, личность, повтор видео или другие подмены. В JSON всегда `motion.antiSpoofingVerified: false`; `motion.status: passed` означает только выполненное движение. Пропуск даёт `skipped`, недоступность модели/камеры — `unavailable`; эти состояния никогда не считаются выполненной проверкой. `allStepsPassed` включает обе автоматические проверки фото и выполнение движения.

### Снимки и переходы

После лица запрашивается задняя камера, после паспорта — фронтальная для движения. На шагах фото доступно переключение камеры. После каждого снимка на **1.5 секунды** остаётся точный снятый кадр с анимированной галочкой и названием следующего шага; затем открывается следующая камера. При настройке «уменьшить движение» анимация отключена, подтверждение остаётся. Если у устройства одна камера, браузер может оставить её. При отказе камера показывает понятную ошибку с повтором; первый снимок сохраняется при повторе второго шага.

Сохраняется **тот же кадр canvas, который прошёл проверку**, в JPEG (длинная сторона до 960 px), без перспективной коррекции документа. Видео заполняет экран через `object-fit: cover`; анализ и рамки используют ту же область кадрирования. Фронтальное превью зеркальное, сохранённое фото — без зеркального отражения. Таймер не засчитывает скрытую вкладку, открытые подсказки или повторно прочитанный видеокадр.

После завершения или пропуска третьего шага видеотреки останавливаются. В ручном режиме камера отключается уже после второго снимка, до экрана недоступной проверки движения. Фотографии находятся только в оперативной памяти страницы: нет API загрузки, localStorage, IndexedDB или аналитики. Пользователь может скачать каждый JPEG и отчёт JSON. JSON содержит параметры и проверки, без фотографий. «Пройти ещё раз» удаляет предыдущий результат из состояния страницы.

В «Диагностике» видны условия текущего шага, углы головы, длительность обработки и переключатель точек/контура. Пороговые значения находятся в `src/geometry.js` (`LIMITS` и функции оценки).

## Проверка

```sh
npm test
npm run build
```

44 автоматических теста проверяют непрерывность таймера, сброс при пропусках кадров, геометрию кадрирования, условия лица, выход документа за рамку, реальную обработку OpenCV, восстановление известных углов через `solvePnP`, обе ориентации сгиба, подсветку отдельных углов, ранние подсказки, круговое движение с шумом и пропусками, сглаживание выбросов, восстановление после короткой потери, отбрасывание неподвижности и допуски первого шага +15%, выбор ручного режима, измерение скорости, таймауты и отмену ожидания модели.

Дополнительные проверки при работающем `npm run dev:http`:

- `/tests/browser.html` — загрузка настоящих MediaPipe и OpenCV, обнаружение 478 точек на публичном тестовом портрете, оценка положения, поиск синтетического документа.
- `/tests/workflow.html` — настоящие детекторы и синтетические `canvas.captureStream()` вместо камеры. Первые два шага проходят автоматически. Неподвижный портрет на третьем шаге не проходит круг; его можно явно пропустить. Итог: `E2E PASS · 2 PHOTOS · TRANSITIONS ≥ 1.5s · ALL TRACKS STOPPED`.
- `/tests/workflow.html?scenario=motion` — полный положительный сценарий: реальные детекторы первых двух шагов и **синтетические 3D-проекции точек** третьего, с настоящим преобразованием точек лица и контроллером движения. Это проверка интеграции, не проверка liveness на человеке.
- `/tests/workflow.html?scenario=guidance` — кнопки тестовых сцен: маленький/смещённый разворот, один угол за рамкой, лист без сгиба, правильный разворот.
- `/tests/mobile.html` — экран 390 × 844; `?guidance` — мобильная проверка подсказок, `?guidance&small` — экран 375 × 667.
- `/tests/manual.html` — ручной выбор без импорта моделей; `/tests/manual.html?limited` — симуляция двух логических ядер. После двух снимков и явного завершения без движения проверяются `0 MODEL REQUESTS`, остановка видеотреков и отсутствие заявлений об автоматической проверке.
- `/tests/workflow.html?scenario=slow` — настоящая модель с дополнительной задержкой 300 мс; `?scenario=error` — ошибка распознавания. Проверяется переход на кнопку и отсутствие дальнейших вызовов распознавания.

Тестовые страницы не включаются в production build. Портрет в `tests/fixtures/portrait.jpg` взят из [тестов tensorflow/tfjs-models](https://github.com/tensorflow/tfjs-models/blob/master/face-landmarks-detection/test_data/portrait.jpg). Реальная съёмка на конкретном iPhone/Android требует проверки на устройстве; автоматические тесты её не заменяют.
