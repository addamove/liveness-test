# В кадре — локальный прототип

Четыре шага: фото лица → паспорт через OpenCV → паспорт через DocAligner → круговое движение головы → результат с тремя фотографиями, таблицей сравнения и скачиваемым JSON. Интерфейс на русском, адаптирован под телефон.

## Запуск

Требуются Node.js 20.19+ и OpenSSL.

```sh
git clone https://github.com/addamove/liveness-test.git
cd liveness-test
npm install
npm run dev
```

`npm install` копирует WASM из npm-пакетов и скачивает Face Landmarker и DocAligner из официальных источников в `public/models/`. Версии зависимостей и SHA-256 весов зафиксированы. Проверенные локальные файлы используются повторно. Во время работы модели и приложение загружаются только с локального компьютера. Интернет нужен для первоначальной установки.

`npm run dev` запускает:

- **HTTPS, порт 5173** — приложение, доступное в локальной сети.
- **HTTP, порт 5174** — страница подключения с QR-кодом, публичным сертификатом и инструкцией для iOS / Android.

Актуальные IP-адреса выводятся в терминале: страница подключения `http://<LAN-IP>:5174` и демо `https://<LAN-IP>:5173`. После изменения сети перезапустите сервер: он выпустит новый сертификат с актуальным IP.

### Телефон

1. Подключите телефон и компьютер к одной Wi-Fi сети.
2. Откройте HTTP-страницу подключения из терминала в Safari или Chrome.
3. Скачайте и установите **V Kadre Local Demo CA**. На iPhone также включите полное доверие: Настройки → Основные → Об этом устройстве → Доверие сертификатам. Подробные шаги есть на странице подключения.
4. Перейдите к HTTPS-демо и разрешите камеру.

Камера через обычный `http://192.168…` не работает: браузеру нужен secure context. Для LAN используется отдельный локальный корневой сертификат и подписанный им серверный сертификат. Скрипт **не меняет** системные настройки доверия. После теста удалите установленный сертификат с телефона. Закрытые ключи находятся в `.certs/`, исключены из Git и запрещены к выдаче Vite; не передавайте их другим людям. HTTP-сервер отдаёт только страницу подключения и публичный `root.cer`.

Если телефон не открывает страницу, проверьте Wi-Fi, VPN, сетевую изоляцию клиентов на роутере и разрешение входящих подключений Node.js в брандмауэре. Управляемое корпоративное устройство может запрещать установку пользовательского CA.

### Только компьютер, без сертификата

```sh
npm run dev:http
```

Откройте [http://localhost:5175](http://localhost:5175). Этот сервер слушает только loopback. Браузеры разрешают камеру на localhost без HTTPS.

## Логика

### Выбор шага и отключённая проверка скорости

Над камерой можно выбрать весь сценарий или отдельный тест: лицо, OpenCV, DocAligner, liveness. Отдельный тест сразу использует нужную камеру, завершается собственным результатом и не требует предыдущих снимков. Выбор доступен и на телефоне; его изменение останавливает камеру и workers предыдущего теста. Повтор запускает тот же тест. Адрес `/?step=document-ml` открывает только DocAligner; допустимы также `face`, `document`, `liveness`. Выбор сохраняется в URL после перезагрузки, фотографии не сохраняются.

**Проверка медленного устройства временно отключена** (`DEVICE_PERFORMANCE_CHECKS_ENABLED = false`): число ядер/память, длительность загрузки, скорость inference и частота кадров не вызывают автоматического переключения на кнопку. Прогрев и измерения остаются для диагностики. Запущенное ожидание можно отменить выбором другого теста, остановкой или кнопкой ручной съёмки. Сохранённые пороги `PERFORMANCE_LIMITS` сейчас не применяются к фоллбеку. Настоящая ошибка модели или отсутствие необходимого API по-прежнему позволяют снимать вручную; разрешение камеры обязательно.

Условия геометрии и свежести кадра не изменены: медленные/устаревшие результаты не подтверждают удержание 400 мс. Кнопка «Снимать по кнопке» доступна сразу и не загружает модели. Ручное фото отмечается «Без проверки», пропущенное движение не считается выполненным. Отчёт содержит режим теста, выбранные шаги, фактический backend, измерения и `performanceChecksEnabled: false`.

По умолчанию DocAligner использует **чистый ONNX WASM runtime** (CPU), без WebGPU/Asyncify runtime. В селекторе можно явно выбрать WebGPU (`?backend=webgpu`). Загружаются только модели текущего шага; worker лица завершается перед паспортом, worker DocAligner — перед liveness. OpenCV, если уже загружен в основной поток, остаётся общим модулем до закрытия страницы. На отдельном liveness OpenCV вообще не загружается.

Vite заранее оптимизирует зависимости обоих runtime и MediaPipe. Это предотвращает обнаруженную перезагрузку всего сценария при первой поздней загрузке DocAligner. Нативные перезапуски вкладки на физическом iPhone этим тестом не проверены.

### 1. Лицо

В Face Landmarker передаётся отдельный кадр с длинной стороной не более 640 px, чтобы уменьшить копирование и передачу в worker на телефоне. Точки пересчитываются в координаты полного кадра; размер сохраняемого фото и геометрические допуски не меняются.

Используется **MediaPipe Face Landmarker** из `@mediapipe/tasks-vision` 1.1.1, модель `face_landmarker/float16/1`. Legacy FaceMesh и TFJS-обёртка удалены. Модель работает в Web Worker, VIDEO mode, `numFaces: 2`, GPU с резервным CPU. Возвращаются 478 точек, включая радужки; нормализованные координаты переводятся в пиксели текущего кадра. Условия автоселфи и допуски +15% сохранены.

Условия:

- В видимой области ровно одно лицо.
- Все точки контура лица внутри овала, лицо расположено по центру и занимает не менее 62% высоты овала.
- Поворот головы: yaw ≤ 14.95°, pitch ≤ 17.25°, roll ≤ 11.5° по модулю. Углы оцениваются через OpenCV `solvePnP` по шести точкам и канонической 3D-геометрии MediaPipe, с приближёнными параметрами камеры.
- Оба глаза открыты. Радужки примерно по центру глаз; допустимое отклонение относительно ширины глаза: горизонтальное ≤0.23, вертикальное ≤0.115. Допуски взгляда и поворота головы расширены на 15% относительно первой версии. Условия рамки, открытых глаз и удержания 400 мс сохранены.
- Условия непрерывно выполняются **не менее 400 мс**, минимум на трёх свежих проанализированных кадрах. Любое нарушение или промежуток между кадрами >350 мс сбрасывает таймер. Долгая обработка >350 мс тоже не засчитывается.

Уверенное направление взгляда на оптическую ось по обычной RGB-камере не гарантируется. Это эвристика по радужкам и повороту головы, без индивидуальной калибровки, не eye tracker и не liveness/anti-spoofing. Фотография лица на экране тоже может пройти условия — прототип не проверяет живость.

### 2. Раскрытый паспорт

Используется **OpenCV.js 4.12**: контуры Canny и пороговая сегментация, объединение разрывов, выпуклая оболочка и четырёхугольник. Детектор не является обученной моделью. Интерфейс поддерживает два положения разворота: **две страницы рядом** (рамка 1.42:1) и **одна над другой** (рамка 1:1.42).

Поиск кандидата отделён от допуска к снимку. Уже небольшой, смещённый или обрезанный прямоугольник получает янтарный контур. Подсказки предлагают приблизить/отдалить камеру, сдвинуть паспорт в конкретную сторону, выровнять его или показать сгиб. Направления учитывают зеркальное превью. Четыре угла рамки оцениваются отдельно: угол зелёный только при реально видимом угле документа внутри рамки и рядом с соответствующим углом рамки. Потеря контура сразу убирает зелёную подсветку.

Для автоматического фото одновременно нужны:

- Все четыре края полностью видны в видеокадре, углы внутри рамки и возле её соответствующих углов.
- Площадь ≥55% рамки, пропорции соответствуют выбранному развороту, умеренная перспектива.
- Видимый **центральный сгиб**. Кандидат временно выравнивается перспективным преобразованием; ищется непрерывная тёмная полоса около середины между страницами. Для вертикального разворота сгиб горизонтальный.
- Смещение углов <2.5% ширины рамки между кадрами и все условия соблюдены 400 мс.

Обычный ровный лист без сгиба автоснимок не проходит. Но это **эвристика признаков разворота**, которая не гарантирует, что объект — открытый паспорт: напечатанная линия или похожая тень могут имитировать сгиб. Блики, бесконтрастные края и слабо выраженный сгиб дают ложные отказы. Нужен контрастный фон, ровный свет и достаточно расправленные страницы. В ручном режиме интерфейс просит раскрыть паспорт, но не проверяет его.

Для надёжного различения открытого и закрытого паспорта нужен отдельный обученный классификатор/сегментатор и размеченные примеры обоих состояний, разных фонов, освещения и устройств. Текущая настройка OpenCV меняет геометрические и контрастные пороги, без «дообучения». Содержимое, тип, подлинность паспорта и качество фото не проверяются.

### 3. Паспорт через DocAligner

Углы ищет **DocAligner LCNet100** через `onnxruntime-web` 1.30.0 в отдельном Web Worker. Веса (~4.8 MB) загружаются перед этим шагом, затем выбирается WebGPU или WASM CPU. WASM использует один поток, без требования cross-origin isolation. Кадр уменьшается до 256 × 256, BGR NCHW / 255, как в Python-референсе. Из четырёх heatmap с порогом 0.3 берутся центры крупнейших связных областей. Декодирование выполняется в разрешении heatmap с масштабированием координат; это браузерная адаптация, не побитовая копия Python-постпроцессинга. Отсутствующий угол не восстанавливается OpenCV.

Оба детектора получают кадр высотой до 640 px. Проверки рамки, размера, видимости углов, геометрии, центрального сгиба, стабильности и удержания 400 мс общие. DocAligner предсказывает внешние углы; сгиб на обоих шагах проверяет одна функция OpenCV. Между шагами 2 и 3 камера и выбранная ориентация сохраняются. Постарайтесь не менять фон, освещение и положение паспорта.

Результат содержит отдельные фото OpenCV и DocAligner и таблицу: среднее время обработки, p95, число кадров с четырьмя углами / число замеров и режим снимка. Первые четыре прогревочных кадра исключены. Время включает обработку и проверку сгиба; у DocAligner также обмен с worker. Измерения охватывают всю попытку, в отличие от скользящего окна фоллбека. Нахождение контура не является метрикой точности, последовательная съёмка не заменяет сравнение на одних и тех же кадрах. JSON хранит результаты каждого детектора отдельно.

### 4. Круговое движение головы

Используется уже загруженный Face Landmarker; дополнительная модель не загружается. Курсор четвёртого шага вычисляется по положению носа относительно линии глаз и подбородка, с нормализацией масштаба, сдвига лица и наклона головы. Это устраняет скачки между решениями `solvePnP`; 3D-оценка остаётся на первом шаге. Медиана трёх отсчётов и сглаживание с постоянной 150 мс подавляют дрожание; одиночные большие выбросы не двигают курсор и не дают прогресса. После 450 мс прямого устойчивого положения запоминается нейтральный поворот. Затем пользователь плавно следует за точкой по часовой стрелке и возвращается в центр. Белая точка показывает оценку движения головы, зелёная — следующую цель.

Проверяются девять последовательных секторов полного круга (последний замыкает первый) и устойчивый возврат в центр. В каждом секторе нужно ненадолго задержаться. Масштаб управления: 18 условных единиц по горизонтали и 13 по вертикали; это приближённые ориентиры движения, не точные углы головы. Радиус попадания допускает диапазон 55–165%, угловой допуск — около 26°.

Краткая потеря лица или сбой до 1.2 секунды ставит проверку на паузу и сохраняет пройденные точки. Длительная потеря лица требует новой калибровки. Центр круга и выбросы не дают прогресса; сглаженная траектория сама по себе тоже не может заработать точку — проверяются и текущие исходные координаты. При движении лицо может немного выходить за овал, если остаётся достаточно крупным и около центра. Скрытие вкладки/открытие справки сбрасывает задание; изменение размера экрана не стирает нормализованную калибровку. Полное выполнение занимает не менее четырёх секунд. Настройки и логика — в `src/liveness.js`.

Это **демо задания на движение**, не надёжный liveness/PAD: оно не проверяет глубину, личность, повтор видео или другие подмены. В JSON всегда `motion.antiSpoofingVerified: false`; `motion.status: passed` означает только выполненное движение. Пропуск даёт `skipped`, недоступность модели/камеры — `unavailable`; эти состояния никогда не считаются выполненной проверкой. `allStepsPassed` проверяет только выбранные шаги; в полном сценарии это три автоматические проверки фото и выполнение движения.

### Снимки и переходы

После лица запрашивается задняя камера, после второго снимка паспорта — фронтальная для движения. На шагах фото доступно переключение камеры. После каждого снимка на **1.5 секунды** остаётся точный снятый кадр с анимированной галочкой и названием следующего шага; затем открывается следующая камера. При настройке «уменьшить движение» анимация отключена, подтверждение остаётся. Если у устройства одна камера, браузер может оставить её. При отказе камера показывает понятную ошибку с повтором; первый снимок сохраняется при повторе второго шага.

Сохраняется **тот же кадр canvas, который прошёл проверку**, в JPEG (длинная сторона до 960 px), без перспективной коррекции документа. Видео заполняет экран через `object-fit: cover`; анализ и рамки используют ту же область кадрирования. Фронтальное превью зеркальное, сохранённое фото — без зеркального отражения. Таймер не засчитывает скрытую вкладку, открытые подсказки или повторно прочитанный видеокадр.

После завершения или пропуска четвёртого шага видеотреки останавливаются. В ручном режиме камера отключается уже после третьего снимка, до экрана недоступной проверки движения. Фотографии находятся только в оперативной памяти страницы: нет API загрузки, localStorage, IndexedDB или аналитики. Пользователь может скачать каждый JPEG и отчёт JSON. JSON содержит параметры и проверки, без фотографий. «Пройти ещё раз» удаляет предыдущий результат из состояния страницы.

В «Диагностике» видны условия текущего шага, углы головы, длительность обработки и переключатель точек/контура. Пороговые значения находятся в `src/geometry.js` (`LIMITS` и функции оценки).

## Проверка

```sh
npm test
npm run build
```

54 автоматических теста проверяют непрерывность таймера, сброс при пропусках кадров, геометрию кадрирования, условия лица, выход документа за рамку, реальную обработку OpenCV, восстановление известных углов через `solvePnP`, обе ориентации сгиба, подсветку отдельных углов, ранние подсказки, круговое движение с шумом и пропусками, сглаживание выбросов, восстановление после короткой потери, отбрасывание неподвижности и допуски первого шага +15%, выбор ручного режима, измерение скорости, прогрев, таймауты и отмену ожидания модели.

Дополнительные проверки при работающем `npm run dev:http`:

- `/tests/browser.html` — загрузка настоящих Face Landmarker, DocAligner и OpenCV, обнаружение 478 точек на публичном тестовом портрете, оценка положения, поиск синтетического документа обоими детекторами и отсутствие ML-детекции на пустом фоне. `?webgpu` проверяет DocAligner на GPU; по умолчанию используется чистый WASM.
- `/tests/workflow.html` — настоящие детекторы и синтетические `canvas.captureStream()` вместо камеры. Первые три шага проходят автоматически. Неподвижный портрет на четвёртом шаге не проходит круг; его можно явно пропустить. Итог: `E2E PASS · 3 PHOTOS · TRANSITIONS ≥ 1.5s · ALL TRACKS STOPPED`.
- `/tests/workflow.html?scenario=motion` — полный положительный сценарий: реальные детекторы первых трёх шагов и **синтетические 3D-проекции точек** четвёртого, с настоящим преобразованием точек лица и контроллером движения. Это проверка интеграции, не проверка liveness на человеке.
- `/tests/workflow.html?scenario=guidance` — кнопки тестовых сцен: маленький/смещённый разворот, один угол за рамкой, лист без сгиба, правильный разворот.
- `/tests/mobile.html` — экран 390 × 844; `?guidance` — мобильная проверка подсказок, `?guidance&small` — экран 375 × 667.
- `/tests/manual.html` — ручной выбор без импорта моделей; `/tests/manual.html?limited` — симуляция двух логических ядер. Даже при двух ядрах ручной режим теперь выбирается явно. После трёх снимков и явного завершения без движения проверяются `0 MODEL REQUESTS`, остановка видеотреков и отсутствие заявлений об автоматической проверке.
- `/tests/workflow.html?scenario=warmup` — задержка первых четырёх вызовов лица до 2.1 секунды и один поздний вызов +1.8 секунды: автосъёмка должна восстановиться без переключения на кнопку.
- `/tests/workflow.html?scenario=slow` — задержка 400 мс: модель продолжает работать, автоматического фоллбека нет. `?scenario=error` проверяет реальную ошибку и остановку worker.
- `/tests/steps.html?step=document-ml` — отдельный снимок DocAligner настоящей моделью, без загрузки лица; проверяется остановка камеры и workers. `step=document` проверяет OpenCV, `step=liveness` — отдельный запуск/пропуск движения без OpenCV.

Тестовые страницы не включаются в production build. Портрет в `tests/fixtures/portrait.jpg` взят из [тестов tensorflow/tfjs-models](https://github.com/tensorflow/tfjs-models/blob/master/face-landmarks-detection/test_data/portrait.jpg). Реальная съёмка на конкретном iPhone/Android требует проверки на устройстве; автоматические тесты её не заменяют.
